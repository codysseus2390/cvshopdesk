# Lovable Dependency Audit

**Date:** 2026-09-18  
**Branch:** `audit/lovable-dependency-audit`  
**Auditor:** Claude Code (Sonnet 4.6)  
**Scope:** All Lovable-related dependencies, files, configuration, integrations, generated
artifacts, build settings, metadata references, deployment assumptions, backend dependencies,
and sync behaviors in the `cvshopdesk` repository.

---

## Summary

The project was originally scaffolded and primarily built inside Lovable. It is actively
migrating toward a standard GitHub → Vercel → Supabase workflow, but **several
production-critical Lovable dependencies remain and cannot be removed without a migration
plan**.

Key risks:
- The **entire build system** is driven by `@lovable.dev/vite-tanstack-config`. The app
  cannot be built without it.
- **Google OAuth sign-in** runs through `@lovable.dev/cloud-auth-js`. Removing it breaks
  authentication.
- The **Cedar Valley logo** is served from a Lovable CDN path (`/__l5e/assets-v1/...`).
  This URL likely 404s outside of Lovable-hosted environments. **Needs verification on
  Vercel.**
- The live production URL `https://cvshopdesk.lovable.app` is hosted by Lovable. No
  Vercel production deployment has been confirmed as the primary URL yet.

## Recommended Migration Order

1. **Verify the asset URL first** — check whether `/__l5e/assets-v1/...` resolves on Vercel.
   If it 404s, the logo is already broken in production and this is an immediate fix.
2. **Verify Supabase OAuth redirect URIs** — open Supabase Auth → URL Configuration for
   project `xbpkvbjmclokmbumhymg` and confirm the Vercel URL is listed. Add it if missing.
3. **Migrate Google OAuth** — replace `lovable.auth.signInWithOAuth()` with direct
   `supabase.auth.signInWithOAuth()`. This unblocks removal of `cloud-auth-js` and
   `src/integrations/lovable/index.ts`.
4. **Remove safe files** — after (3), clean up `lovable-error-reporting.ts`, its references
   in `__root.tsx`, `previewAuthStorage.ts`, and the Lovable-Cloud error strings.
5. **Migrate the build config** — replace `@lovable.dev/vite-tanstack-config` with a
   hand-written `vite.config.ts`. This is the highest-risk migration step; test thoroughly.
6. **Confirm Vercel as primary host** — once build and auth are verified on Vercel,
   update `README.md` and consider retiring the Lovable project.
7. **Final cleanup** — remove `.lovable/` directory, `LOVABLE_NOTES.md` (or archive it),
   remaining `@lovable.dev` entries in `bunfig.toml`.
